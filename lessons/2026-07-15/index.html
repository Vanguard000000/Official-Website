Export on export.

The camera loop should track and draw. It should not rebuild a JSON-ready research artifact 10–30 times every second.

Why this matters. MediaPipe's Web detectForVideo() calls are synchronous and block the main thread. The code then adds another model, smoothing, drawing, metrics, and deep artifact construction to the same frame budget.

What the audit found

  • detectFrame() runs Pose Landmarker and periodically Hand Landmarker on the main thread (lines 1974–1984).
  • buildFrameSnapshot() creates a timestamp, model/video metadata, metrics, kinematics, and copied objects for every pose and hand landmark (lines 1929–1964).
  • tick() calls that builder every processed frame (lines 2061–2067), although the JSON is downloaded only when the user clicks Export (lines 2002–2015).
  • Pose and hand arrays are mapped through serializeLandmark(), so a visible pose plus one hand allocates at least 54 landmark objects per processed frame, before the wrapper objects and smoothing arrays.
  • Several metric elements are written every frame (lines 1992–2000 and 2049–2068).
  • resizeCanvasToViewport() is called from the hot loop (line 2030) as well as real resize handlers.
  • No completed June 16 performance results file exists in this repo. Today's first five runs are the baseline; do not invent one.
Required change: construct the snapshot only when Export is requested. Keep only the latest frame data needed by the UI. Move JSON-ready serialization—ISO timestamp, metadata wrappers, and copied landmark objects—behind exportCurrentFrame(). Preserve the export schema and fail clearly if no frame has been captured.

Do not touch these knobs

Keep both models, delegate, confidence thresholds, detection intervals, smoothing, and camera constraints unchanged. This experiment isolates artifact allocation from model inference.

Protocol

  1. Start python3 -m http.server 5174 from the repo root and open http://localhost:5174/mediapipe-lab/sims/pose-estimation/.
  2. Fill in plan.md before code changes.
  3. Enable pose and hand overlays. Warm up for 10 seconds, then record five 10-second runs in results.md.
  4. Export one frame before the change and save it for schema comparison.
  5. Move construction behind the action, repeat five runs, and export again. Compare top-level keys and pose/hand counts.
